# Шаблоны уведомлений вебинаров в Supabase

## Что изменилось

Тексты уведомлений и Telegram-вложения не хранятся в коде и не используют переменные окружения. Для каждого вебинара и каждого момента напоминания используется отдельная строка таблицы `public.webinar_notification_templates`.

| Поле | Назначение |
|---|---|
| `id` | Внутренний идентификатор записи. |
| `webinar_id` | Идентификатор вебинара в текстовом виде. |
| `reminder_type` | Стандартный тип либо `custom_<минуты>_minutes` для произвольного времени. |
| `offset_minutes_before` | Сколько минут до начала вебинара нужно отправить уведомление. |
| `message_text` | Текст Telegram-сообщения. Поддерживает `{{webinar_title}}`, `{{webinar_date}}` и `{{webinar_time}}`. |
| `file_id` | Telegram `file_id` прикреплённого документа, если он есть. |
| `file_type` | MIME-тип документа или имя файла, полученное из Telegram. |
| `created_at`, `updated_at` | Время создания и последнего обновления. |

Для одного вебинара можно хранить только один шаблон на один и тот же интервал до начала. Например, нельзя одновременно создать два уведомления за 90 минут.

## 1. SQL-миграции

Если первоначальная миграция шаблонов **ещё не выполнялась**, выполните в Supabase SQL Editor:

```text
supabase/webinar_notification_templates.sql
```

Она создаст финальную структуру и автоматически добавит четыре текущих шаблона — за 3 дня, 1 день, 6 часов и 15 минут — для **всех уже существующих вебинаров**. Сохранённые вручную строки при повторном запуске не перезаписываются.

Если прежняя версия `webinar_notification_templates.sql` **уже была выполнена**, последовательно примените:

```text
supabase/webinar_notification_templates_custom_offsets.sql
supabase/webinar_reminder_sends_custom_types.sql
```

Последняя миграция нужна, чтобы существующий журнал `webinar_reminder_sends` мог фиксировать однократную отправку произвольных типов. Таблицу `webinar_reminder_sends` не удаляйте; `webinar_registrations` не изменяется.

## 2. Добавление или изменение стандартного уведомления

1. Откройте личный чат с ботом под реальной ролью `admin` и отправьте `/start`.
2. Нажмите **«🔔 Уведомления»**.
3. Выберите вебинар.
4. Выберите один из стандартных моментов: **«За 3 дня»**, **«За 1 день»**, **«За 6 часов»** или **«За 15 минут»**.
5. Нажмите **«📝 Изменить текст»**.
6. Отправьте новым сообщением полный текст уведомления.

Бот сохранит текст в `message_text`; в код и `.env` его добавлять не нужно.

## 3. Новое уведомление на другое время

1. В карточке нужного вебинара нажмите **«➕ Другое время до вебинара»**.
2. Отправьте целое число минут до старта. Например, `90` создаст уведомление за 1 час 30 минут, а `2880` — за 2 дня.
3. Откроется карточка нового уведомления. Нажмите **«📝 Изменить текст»** и отправьте текст.
4. При необходимости добавьте файл через **«📎 Прикрепить PDF / документ»**.

Внешний cron проверяет эти интервалы тем же образом, что и четыре стандартных. Окно срабатывания составляет 15 минут, поэтому расписание внешнего cron должно оставаться не реже одного запуска в 5 минут.

## 4. Прикрепление либо удаление PDF/документа

1. В карточке выбранного типа нажмите **«📎 Прикрепить PDF / документ»**.
2. Отправьте боту PDF или иной Telegram-документ следующим сообщением.
3. Бот возьмёт `file_id`, имя/MIME-тип из Telegram update и сохранит их в `file_id` и `file_type`.

Администратор не вводит `file_id` вручную. Для удаления ранее сохранённого документа нажмите **«🗑 Удалить прикреплённый файл»**. Кнопка **«📭 Сохранить без файла»** оставляет текст, но очищает вложение.

## 5. Как проверить сохранение

После сохранения бот снова показывает карточку шаблона. В ней будет статус вида:

```text
текст: ✅, файл: ✅ (application/pdf)
```

Дополнительно откройте **«🧪 Тест уведомлений»**, выберите тот же вебинар и нужный шаблон. В списке теста будут и стандартные, и произвольные интервалы. Тестовая отправка придёт только текущему admin и не создаст строк в `webinar_reminder_sends`.

## 6. Как cron получает шаблон

Внешний cron вызывает `GET /api/cron/webinar-reminders` с `Authorization: Bearer <CRON_SECRET>`. При каждом запуске сервер:

1. выбирает активный будущий вебинар и зарегистрированных получателей;
2. получает все строки `webinar_notification_templates` этого вебинара;
3. определяет, наступило ли время по `offset_minutes_before`;
4. отправляет `message_text`, подставляя поддерживаемые значения `{{webinar_title}}`, `{{webinar_date}}` и `{{webinar_time}}`;
5. если существует `file_id`, затем отправляет документ через Telegram `sendDocument`;
6. для `15_minutes` добавляет кнопку **«🚀 ВОЙТИ НА АРЕНУ DISTRICT»** с URL из `webinars.registration_url`;
7. использует `webinar_reminder_sends` для однократности отправки.

## 7. Переменная старого PDF-гайда

`WEBINAR_1_DAY_GUIDE_FILE_ID` больше не используется кодом. Она удалена из локального `.env.local`; удалите её также из переменных окружения Vercel при следующей настройке проекта.
