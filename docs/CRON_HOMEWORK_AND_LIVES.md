# Жизни и дедлайны ДЗ — без обязательного cron

Оба процесса можно вести **без внешнего планировщика**. Эндпоинты `/api/cron/*` оставлены как опция, если захотите более точные TG-напоминания.

## 1. Восстановление жизней (месяц)

**Как работает сейчас**

1. Админ открывает главную TG-панели в первые **1–3** дня месяца (МСК).
2. Если есть ученики с жизнями &lt; max — блок «ЖИЗНИ ЗА МЕСЯЦ» и кнопка  
   `❤️ Восстановить жизни всем (N)`.
3. Кнопка всегда доступна: **Прочее → Восстановить жизни всем (месяц)** (`al:rm`).
4. Вызов идемпотентен по `period_key` (YYYY-MM МСК). Заморозка **снимается**, если после restore жизни &gt; 0.

Опциональный cron (если нужен автозапуск без захода админа):

```bash
curl -sS -H "Authorization: Bearer $CRON_SECRET" \
  "https://YOUR_HOST/api/cron/lives-monthly-restore"
```

## 2. Напоминания о дедлайне ДЗ

**Старт таймера 72ч:** только Play на `/cabinet/lesson` (watch-live / watch-recording).

**Без cron — ленивые проверки:**

| Когда | Что происходит |
|---|---|
| Ученик открывает занятие | Проверка его активных дедлайнов → TG 12ч/6ч/2ч/overdue |
| Куратор открывает кабинет | Sweep по его ученикам |
| Админ открывает главную | Лёгкий sweep (до ~80 строк) |

Минус: ученик, который **никогда** не заходит и куратор/админ тоже молчат, может не получить напоминание вовремя. Просрочка всё равно видна в UI по `deadline_at`.

Опциональный cron для точных окон:

```bash
# каждые 10–15 минут
curl -sS -H "Authorization: Bearer $CRON_SECRET" \
  "https://YOUR_HOST/api/cron/homework-deadlines"
```
